## 1. 验收清单（对照说明书第十四章）

| # | 验收标准 | 实现位置 | 验证方法 |
|---|---|---|---|
| 1 | 安装后能引导开启无障碍服务 | `HomeScreen` 状态卡 + 「去开启无障碍服务」（逐级降级跳转）、分品牌路径提示 | 首启首页显示未开启 + 引导按钮 |

### D 组：倒计时按钮（v0.4.0 新增）

> 触发原因：用户反馈存在 `跳过n` 与 `n跳过` 两种形态（n 为倒计时，通常 1~5 秒）。
> D1~D4 可用 `tools/verify_countdown_patterns.py` 与 `tools/java/VerifyCountdown.java` 离线自检。

| # | 用例 | 前置 | 步骤 | 期望结果 |
|---|---|---|---|---|
| D1 | 学习「数字在后」 | 无障碍已开启，开屏按钮显示 `跳过3` | 学习模式里点该按钮 | 候选规则的关键词为 `跳过`，说明中标注「不限倒计时数字」；保存后倒计时变成 5/2/1 仍能命中 |
| D2 | 学习「数字在前」 | 开屏按钮显示 `3跳过` | 同上 | 同样归一成 `跳过`（旧版会整串当成 `3跳过`，只在倒计时=3 时命中） |
| D3 | 英文倒计时 | 按钮显示 `Skip in 3s` | 同上 | 归一成 `skip`；倒计时变化后仍命中 |
| D4 | 全角数字 | 按钮显示 `跳过３`（全角） | 同上 | 能识别（条件含 `０-９`） |
| D5 | 内置规则升级 | 曾安装 v0.3.0 及更早版本 | 覆盖安装 v0.4.0 后打开规则页 | 高德规则 JSON 的倒计时条件已更新为**双排列**且 `version` 为 2（保留用户的启用/禁用状态） |
| D6 | 纯数字不误判 | — | 学习模式点到按钮文字为 `3` 的节点 | 该样本不生成文字候选（`keywordOf` 返回 null），不会学出「数字」规则 |

### 真机测试步骤（高德地图，回归）

1. 构建安装（Android Studio Sync → Run 到 Android 8.0+ 真机）；
2. 首页开启无障碍服务（设置 → 无障碍 → 已安装的应用 → 开屏跳过服务）；
3. **完全退出高德地图**（最近任务划掉）→ 重新打开；
4. 开屏出现「跳过 / 关闭 / ✕」按钮（任意角落）→ 8 秒内应自动点击一次进入主页；
5. 「日志」页核对：包名 `com.autonavi.minimap`、规则「高德地图开屏跳过」、节点文本、动作与结果；
6. 负向验证：连续开屏仅一条成功点击（最多一次）；打开非目标 App 无 AUTO_CLICK 日志；
7. 位置回归：确认屏幕正中央的广告内容**没有**被点击。

## 3. v0.4.0 优化记录（倒计时按钮）

- **新增 `engine/SkipTextNormalizer`**：把按钮文本归一成稳定关键词；
  语义词优先（跳过/关闭/skip/close/✕…），否则剥掉**两端**的数字与连接符
  （空格、全角空格、`s/S`、`秒`、`后`、`·`、`.、:：,，、（）[]【】|/\-—`）。
  旧版 `LearningController.keywordOf` 只剥尾部数字，导致 `3跳过` 整串被当关键词；
- **`patternForCountdownKeyword()`**：生成 `跳过 | 数字*连接符*跳过 | 跳过连接符*数字+` 三段交替，
  学到某一瞬间的倒计时文本后，倒计时变化或排列不同都能命中；关键词含数字时退化为精确字面量；
- **内置规则倒计时条件改为双排列**，并兼容全角数字 `０-９`、`s/秒/后`、英文 `in/after`
  （如 `Skip in 3s`）；`BuiltinRules.VERSION` 1 → **2**，确保老用户升级后生效；
- **词表统一**：`LearningController.SKIP_HINTS` 改为引用 `SkipTextNormalizer.KEYWORDS`，
  消除两处定义漂移的风险；
- **修掉一个崩溃 bug**：连接符字符类写成 `【】-—`，被解析为 `】`(U+3011) → `—`(U+2014)
  的**逆序范围**，Java/Python 正则在编译期即抛异常；**该分支只在「数字在前」时走到**，
  由新增验证脚本抓出。连字符已移到字符类末尾；
- **两道验证**：
  - `tools/verify_countdown_patterns.py`：Python 等价模型，**直接从 `BuiltinRules.kt` 读取规则 JSON**，避免脚本与规则漂移；含防误触负例；
  - `tools/java/VerifyCountdown.java`：用**真实 `java.util.regex` 引擎**（与 Kotlin `Regex` 同源）验证编译与匹配，覆盖 20 组归一化、9 组学习场景、11 组内置规则、7 组负例；
- **UI 文案**：候选规则说明明确写出「不限倒计时数字」；倒计时样本的推荐度 92 → 94。

## 3.1 v0.3.0 优化记录（匹配通用性）

- **位置硬过滤 → 位置加权**（`RuleMatcher.positionScore`）：四角 25 / 顶部边缘 22 / 底部边缘 18 / 左右边缘 10 / **屏幕中间 0**；`area` 留空即全屏匹配。旧版 `TOP_RIGHT_BONUS` 只认右上角，且内置规则把 `top_right` 写进条件做硬过滤；
- **新增 `icon_button` 条件**（`RuleMatcher.isIconButtonCandidate`）：可点击 + 无文字 + 无描述 + 宽 ≤22% 屏宽、高 ≤18% 屏高 + 位于边缘区，覆盖纯 ✕ 图标按钮；
- **尺寸分**（`sizeScore`）：宽度 ≤12% → 15 分、≤22% → 10 分、≤35% → 5 分，越紧凑越像关闭按钮；
- **同分排序改为「离最近四角更近者优先」**：旧版固定按到右上角距离排序；
- **负名单扩充**：新增「立即 / 安装 / 领取 / 授权 / 允许 / 升级 / 更新 / 查看详情 / 了解更多」，防止把广告 CTA 按钮当成关闭按钮；
- **关键词扩充**：叉号系 `✕✖✗×⨯╳❌❎`、繁中 `跳過/略過/關閉`、英文 `skip/close/dismiss/cancel`；
- **学习捕获兜底改名并放宽**（`topRightCandidate` → `bestSkipCandidate`）：从「只找右上角」改为**四角 + 上下边缘全扫**，按关键词 / 可点击 / 尺寸 / 靠近角落综合打分；
- **误点过滤放宽**（`isLookingLikeSkipButton`）：从「上方 35%」改为「任意边缘区 + 可点击 + 宽度 <60% 屏宽」，否则底部的关闭按钮点了也不被采信；
- **位置兜底去掉半屏硬编码**（`safeFallback`）：删除「纵向 >45% 直接放弃」，改为采用用户实际点击坐标（仅做 1% 屏幕内边距钳制），并按落点生成区域说明；
- **新增「按纯图标按钮识别」候选**：样本无文字、无描述、无 viewId 时给出 `icon_button` 规则并标记推荐；
- **内置规则版本化升级**（`BuiltinRules.VERSION` + `RuleRepository.load`）：修正「老用户永远拿不到新内置规则」的缺陷，升级时保留用户的启用/禁用选择；
- **规则模板重做**：默认区域从 `top_right` 改为「不限」；新增「× 关闭按钮」「纯图标关闭」「顶部通栏广告」「底部横幅广告」；区域选项增加 顶部/底部；
- **规则编辑器**：新增「也匹配纯图标按钮」开关；修正得分说明文案（原写「+右上角20」）；`normalizeArea` 兼容旧规则的 area 取值；
- **新增自检脚本** `tools/verify_matcher_model.py`：等价模型覆盖四角/边缘/中间/尺寸/防误触底线，可离线复跑（本仓库无单元测试基建）。

## 3.2 v0.2.0 优化记录

- **学习捕获四级取样**（`SkipAccessibilityService.captureLearningClick`）：事件源自身 → 可点击父链（≤6 层）→ 子节点文字（≤3 层，关键词优先）→ 窗口快照候选；彻底摆脱旧版「节点无文字即学习失败」；
- **移除误判逻辑**：旧版用 `SystemClock.uptimeMillis() - event.eventTime > 3000` 判断「3 秒时效」，两个时钟基准不同，实际会把正常点击误判为过期，已删除；
- **学习会话状态机 + 60 秒超时**（`LearningController`）：超时/取消都保留目标包与原因，UI 给出可操作提示；
- **多候选规则 + 推荐度**：一条样本产出文字/描述/viewId/位置等多类候选，按证据强度排序并在 UI 标注推荐；
- **保存前试跑**（`SkipAccessibilityService.evaluateRule`）：用 `NodeCache` 缓存的窗口快照跑一次 `RuleMatcher`，把「能不能命中」提前告诉用户；
- **节点缓存**（`NodeCache`，5 分钟 TTL，仅内存，不上传不落盘）：学习回溯与规则试跑共用，服务释放时清空；
- **事件类型扩展**：新增 `typeViewLongClicked`（长按式跳过）、`typeWindowsChanged`（多窗口/悬浮窗开屏）；
- **无障碍配置增强**：`flagIncludeNotImportantViews`（部分 ROM 把广告节点标记为不重要）、`flagRetrieveInteractiveWindows`（多窗口取活动窗口）、`summary` 说明、`notificationTimeout` 100→150ms；
- **激活探针**：`onServiceConnected` 后 600ms 主动读一次窗口，缓解 MIUI/ColorOS「开了开关没反应」；
- 保留阶段 7-9 优化：日志落盘去抖 500ms、扫描节流 300ms、节点采集超时 300ms/上限 2000/深度 30、正则缓存、节点统一回收、点击失败连续 3 次停止本轮、规则级 minScore 可配。

## 4. 已知限制

- 「冷启动」定义为目标包进入前台（`TYPE_WINDOW_STATE_CHANGED`），热启动同样计入 8 秒窗口；
- 学习模式需 `QUERY_ALL_PACKAGES` 权限才能列出全部本机应用；该权限仅用于**本机**列表展示，不联网、不落盘；若渠道限制该权限，可退回「手动输入包名」入口；
- `icon_button` 是启发式判定（可点击 + 无文字 + 小尺寸 + 位于边缘），理论上仍可能误判；缓解手段：`minScore` 默认 60、中心区域不给位置分、敏感词负名单、每次开屏最多点一次（v0.3.0 起屏幕中央的纯图标不再得分，误点风险已显著降低）；
- 位置兜底候选只在按钮「节点信息完全不可读」时才出现，可能出现漏点（保守优先于误触）；
- 试跑依赖最近一次窗口快照：开屏结束后试跑会提示「没有找到匹配节点」，属正常，不代表规则无效；
- 日志环形上限 500 条；调试节点快照仅保留本次会话（不落盘、不上传）；
- OCR 兜底 / 图像模板匹配为 P2 未实现；
- 规则编辑器：可视化表单已实现（表单 + JSON 双模式）；复杂正则仍可切换 JSON 精确编辑；
- `tools/verify_matcher_model.py` 是**等价模型**而非直接执行 Kotlin 代码，用于快速回归评分逻辑；本仓库暂无 JVM 单元测试基建（离线环境无法获取 JUnit 依赖）。

## 4.1 构建产物核对（每次发版必做）

自动化只能证明「编译通过」，还要证明**配置真的进了 APK**。以下命令可直接复现：

```bat
:: 1) 版本号必须与 git 标签一致
aapt2 dump badging app\build\outputs\apk\debug\app-debug.apk | findstr /C:"package:"

:: 2) 无障碍服务配置的实际打包值（不是看源码 XML，而是看 APK 里的编译结果）
aapt2 dump xmltree app\build\outputs\apk\debug\app-debug.apk --file res/xml/accessibility_service_config.xml
```

v0.3.0 实测结果（2026-09 核对，android.jar 常量真值比对）：

|---|---|---|
| `accessibilityEventTypes` | `0x00400823` | viewClicked(0x1) + viewLongClicked(0x2) + windowStateChanged(0x20) + windowContentChanged(0x800) + windowsChanged(0x400000) |
| `accessibilityFlags` | `0x00000052` | reportViewIds(0x10) + includeNotImportantViews(0x2) + retrieveInteractiveWindows(0x40) |
| `notificationTimeout` | `150` | ✅ 与源码一致 |
| `canPerformGestures` | `true` | ✅ 手势点击可用（ActionExecutor 第 3/4 级依赖） |
| `canRetrieveWindowContent` | `true` | ✅ 可读节点树 |
| `versionCode` / `versionName` | `4` / `0.3.0` | ✅ 与标签 `v0.3.0` 一致 |

另需核对**内置规则升级是否生效**（v0.3.0 新增）：

```bat
:: 内置规则 JSON 结构自检（条件不应再带 area）
python tools\verify_matcher_model.py
```

在手机上则打开「规则 → 高德地图开屏跳过 → 编辑（JSON 模式）」，确认条件里**没有** `"area": "top_right"`，
且存在 `"type": "icon_button"` 条件 —— 说明版本化升级已把新规则写入本机。

> 事件类型常量真值可用 `javap -constants -classpath <sdk>/platforms/android-35/android.jar android.view.accessibility.AccessibilityEvent` 查得，
